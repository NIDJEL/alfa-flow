# Установка и повторный запуск

## Что делает одна команда

1. Находит существующий ALFA FLOW или скачивает исходники в `~/alfa-flow`.
2. Находит Docker; если его нет, устанавливает официальный Docker Desktop/Engine.
3. Ждёт Linux Engine и проверяет Compose с поддержкой `up --wait`.
4. Копирует `.env.example` в `.env`, **только если `.env` ещё нет**.
5. Собирает Go API и React в контейнерах, запускает PostgreSQL → API → web.
6. Ждёт `healthy` всех контейнеров и `status=ready` HTTP API.
7. Открывает `http://localhost:8088/demo`.

Скрипт завершится с ошибкой, если установка или запуск не удались, и выведет
диагностику. Ошибка не удаляет БД. Повтор той же команды безопасен для `.env` и
сохранённых заявок; `git pull`, reset и удаление volume автоматически не выполняются.

## Команды из распакованного/клонированного проекта

| ОС | Команда |
|---|---|
| Windows | `.\scripts\install.cmd` |
| macOS / Linux | `sh ./scripts/install.sh` |

Windows-обёртка использует встроенный PowerShell 5.1 и отключает execution policy
**только для этого процесса**. Глобальные политики компьютера не меняются.
Скрипт также работает в PowerShell 7.

Для установленного и запущенного Docker доступ администратора обычно не нужен.
Go/Node.js/pnpm/Python не нужны для установки. Для отдельного `smoke.sh` нужен Python 3;
Windows `smoke.ps1` дополнительных runtime не требует.

## Установка Docker и ограничения ОС

| ОС | Автоматическая установка | Что может потребовать участия пользователя |
|---|---|---|
| Windows x64 / ARM64 | `winget` → Docker Desktop; без winget — официальный EXE с проверкой Authenticode | UAC/WSL 2, виртуализация, условия Docker Desktop, возможная перезагрузка |
| macOS Intel / Apple Silicon | существующий Homebrew → `docker-desktop`; иначе официальный DMG нужной архитектуры | пароль `sudo`, условия Docker Desktop, системные ограничения версии macOS |
| Linux | официальный `get.docker.com` для dev/demo; Compose из поставки Docker | `sudo`/root, поддерживаемый дистрибутив, работающий init/service manager |

Системные требования и лицензионные условия определяются Docker, а не ALFA FLOW.
Скрипты **не** включают виртуализацию BIOS, не перезагружают компьютер и не принимают
условия Docker Desktop от имени пользователя. После обязательной перезагрузки просто
повторите исходную команду.

На Linux без прав Docker скрипт использует `sudo docker` для текущего запуска,
не добавляя пользователя в привилегированную группу `docker`. Для последующих
команд `stop`, `ps`, `logs` в таком случае также используйте `sudo`.
Недоступный нестандартный Docker context не заменяется автоматически.

Если Docker CLI уже установлен, но Compose отсутствует или слишком стар, обновите
Docker/Compose по инструкции производителя. Скрипт не заменяет произвольную
существующую конфигурацию Docker. Linux без systemd/service, rootless Docker и удалённые
Docker-hosts требуют предварительно настроенного работающего Engine.

## Private GitHub и установка без Git

Репозиторий сейчас закрытый. Публичный `raw.githubusercontent.com` без авторизации
вернёт **404**, даже если адрес правильный. Возможные пути:

- авторизованный `git clone` и локальная команда из таблицы;
- Download ZIP в GitHub под учётной записью с доступом, распаковка и локальная команда;
- `GH_TOKEN` / `GITHUB_TOKEN` с доступом **Contents: read** для этого репозитория.

Команды прямой загрузки с токеном есть в README. При заданном токене установщик
получает архив через GitHub API и не требует Git. Токен не записывается в `.env`,
Git remote и файлы проекта; не передавайте его в URL.

## Настройки окружения

Параметры необязательны; их достаточно задать перед запуском скрипта.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `ALFA_FLOW_DIR` | `~/alfa-flow` | Каталог для скачивания, если скрипт не запущен из проекта |
| `ALFA_FLOW_OPEN_BROWSER` | `1` | `0` отключает открытие браузера (сервер/CI) |
| `ALFA_FLOW_INSTALL_DOCKER` | `1` | `0` запрещает установку Docker, оставляя только проверку/запуск |
| `ALFA_FLOW_WAIT_SECONDS` | `300` | Ожидание Engine, затем готовности контейнеров |
| `ALFA_FLOW_REF` | `main` | Ветка для Git; ref/SHA для GitHub-архива |
| `ALFA_FLOW_REPOSITORY` | `NIDJEL/alfa-flow` | Репозиторий для GitHub API |
| `ALFA_FLOW_REPO_URL` | URL GitHub-проекта | URL для `git clone` |
| `GH_TOKEN` / `GITHUB_TOKEN` | нет | Необязательный токен чтения private-репозитория |

Изменение `ALFA_FLOW_DIR` не перемещает существующий checkout.
`ALFA_FLOW_URL` меняет **только HTTP-проверку/ссылку браузера**, а не порты Compose
и `PUBLIC_ORIGIN`. Для нестандартного порта нужны согласованные Compose override
и API origin; обычному пользователю это не требуется.

Пример запуска без открытия браузера:

```powershell
$env:ALFA_FLOW_OPEN_BROWSER="0"
.\scripts\install.cmd
```

```sh
ALFA_FLOW_OPEN_BROWSER=0 sh ./scripts/install.sh
```

## Управление

Выполняйте из папки проекта:

```sh
docker compose ps                 # состояние
docker compose logs --tail=100    # диагностика
docker compose stop              # остановка с сохранением данных
docker compose up -d --wait       # продолжить без пересборки
```

Для обновления сначала сохраните свои изменения, затем выполните `git pull --ff-only`
и повторите установочную команду. Архивную установку без Git обновляйте скачиванием
нового архива в отдельную папку; не удаляйте существующий volume.

**Опасно:** `docker compose down -v` удаляет БД безвозвратно. Для обычной остановки
эта команда не нужна. `POSTGRES_PASSWORD` не меняет пароль существующего volume.

## Что проверено

23 октября 2026: фактическая Docker-сборка и запуск на Windows, PowerShell 5.1/7,
shell-запуск через Git Bash с установленным Docker, HTTP readiness и smoke A → issued.
Mermaid-диаграммы распарсены и отрендерены локально в Chromium.
Автоустановка Docker на чистых Windows/macOS и реальные macOS-hosts в этом окружении
не проверены; запросы UAC, условия Docker и необходимость перезагрузки зависят от ОС.

Контрактные тесты без сети и без реальной установки Docker:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\tests\install.test.ps1
```

```sh
sh ./scripts/tests/install.test.sh
```

Они проверяют архив private-репозитория, путь с пробелами, повторный запуск без
перезаписи `.env`, `--wait`, неуспешную сборку и отсутствие удаления volume.
Shell-тест также выполнен внутри Linux-контейнера без сети; это проверка логики,
а не утверждение о фактической установке Docker на чистой macOS.
